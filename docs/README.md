# OctoAcme Project Management Docs

This README is the entry point to OctoAcme's project management guidance. The documents below describe the workflows, roles, and practices used to deliver cross-functional projects consistently.

## Project management process overview

OctoAcme follows a lifecycle of initiation, planning, execution, release, and retrospective. Initiation validates the business need, identifies stakeholders, defines measurable outcomes, and documents an initial timeline, risks, and resource needs. Planning turns approved work into a prioritized backlog with acceptance criteria, estimates, ownership, dependencies, a Definition of Done, and milestones.

During execution, teams track work on a project board and deliver iteratively. The Project Manager (PM) coordinates schedules, risks, dependencies, and communications; the Product Manager (PdM) defines outcomes, priorities, and success measures; developers build and test; QA/testing validates quality and acceptance criteria; and stakeholders provide input and approvals. Regular standups, delivery syncs, PM–PdM alignment, stakeholder updates, and demos keep teams informed. Blockers are triaged by the team and escalated through the PM when needed.

Quality assurance is part of development and release: teams use unit tests, integration tests where applicable, smoke tests for critical flows, security scanning, linting, and manual QA when needed. Pull requests should be small, link the relevant issue and acceptance criteria, pass CI checks, and receive the required review approval. Releases include pre-release checks, release notes, smoke tests, rollback or mitigation readiness, deployment verification, and stakeholder communication. Retrospectives after sprints, releases, milestones, or incidents capture learnings and track improvement actions.
